## 七、AGC「点击操作完成快」2666ms 不通过 → 1.0.7 性能修复版（22:00–23:00）

**报告**：「应用存在点击操作完成时延的性能问题」，检测值 **2666.0ms** / 优化目标 2400ms，
环境 WIFI + HarmonyOS 6.1(Mate 60) + API 6.1.1(24) + 中文环境。
**党哥确认：报告是日记的**（⇒ 阅读那侧的性能改动只提交代码，不出包，等下一版带上）。

### 官方口径（查证过，非凭印象）

全名「应用内**点击操作完成快**」；与「点击操作**响应**快」（≤100ms）是**两项不同的检测**。
测的是**墙钟**：手指抬起（ACTION_UP）→ **页面转场 lane 结束**（ABILITY_OR_PAGE_SWITCH 等）。
⇒ **转场画不出来 = lane 结束被推后**；「点击后主线程被同步重活堵住」= 直接超标。
标准值 ≤900ms，AGC 云测目标线 2400ms。

### 根因

`security/KeyCustody.ets` 的 `deriveKek()` 用**同步版** `kdf.generateSecretSync(spec)`，
PBKDF2 **10 万轮**（≈20 万次 SHA-256）跑在**调用线程**上；
调用链「解锁按钮 onClick → recoverByPassword → deriveKek」⇒ 整段 KDF 在 UI 主线程一口气跑完，零帧产出。
SDK 官方注释原文：_"may take a long time and block the main thread … advised to invoke
synchronous API within a child thread to avoid blocking it"_。

### 改动（commit `beea977`）

1. `deriveKek` / `recoverLegacy` 改 `await kdf.generateSecret(spec)`（异步）。
   ⚠️ `recoverLegacy` 由同步函数改 async —— 调用点本来就 `await`，兼容。
2. 新增 `security/KdfParams.ets`（纯逻辑、不引 SDK ⇒ 可单测）作**安全参数唯一真源**。
3. 新增 `test/kdfparams.test.ts`（6 条）锁死参数（漂移 = 老用户打不开日记）。
4. `pages/Unlock.ets` 加 busy 态：点击后同一同步块内换文案（「正在解锁…」/「正在建立保险库…」）+ 禁用。
   校验失败**不置 busy**（先报错别先转菊花）；busy 守卫挡连点。
5. 顺手修 `common/AppMeta.ets` 漂移：1.0.5/1000006 → 1.0.6/1000007
   （1.0.6 发版只改了 app.json5 ⇒ smoke 测试一直红着，10-29 顺手修)。

### 两条安全底线（本次没碰，务必守住）

- **PBKDF2 迭代次数 100000 一个没动** —— 动的是「在哪个线程跑」，不是「算多少次」。
  迭代次数是安全参数、不是性能旋钮；要调低需安全侧签字 + 老库迁移方案。
- **异步版与同步版共用同一 spec** ⇒ 派生结果逐字节一致 ⇒ **老库完全不受影响**。
  依据：SDK `Kdf.generateSecret(spec): Promise<DataBlob>`（d.ts:6212）与 `generateSecretSync` 共用同一 `KdfSpec`；
  官方 PBKDF2 指南把三种调用形式并列列出。
