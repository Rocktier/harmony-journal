## 本版四项新增的实现要点与取舍

### ① 多日记本（`data/Journals.ets` + `pages/Journals.ets`）

- **默认本永远存在**（「生活」），它是**回收港**：删任何别的本，里面的日记都搬回它。
  删本 = 搬日记，**一篇不删** —— 这是本功能最重要的纪律，也是用户最在意的那件事。
- 本列表与条目归属**存在同一份加密索引里**（v3），不是单独文件 ⇒ 零额外 IO。
- 首页切本用横向 Scroll 的 chip（和标签条同构）；**只有一本时不显示 chip 行**
  （「全部」和「生活」指向同一批日记，那是噪音），但「管理本」入口**始终在**。
- 统计/月历/时间轴**按本过滤**（切到空本就是空态，不串数据）。
- ⚠️ ArkUI V1 的 `@Builder` 值参数不随 `@State` 重跑 ⇒ 本页每个 chip 与每行的
  ForEach key **都带上了选中态/展开态后缀**（家族第 4 次同型坑，第 5、6 次实例）。

### ② 每日提示（`data/Prompts.ets`）

- 60+ 条提示文案，**同一天永远给同一条**（按日期确定性取值，不是随机）——
  随机的话用户反复打开会看到不同的话，反而像 bug。
- **只在空正文时出现**（`this.words === 0`）—— 已经在写了就别出主意，那是干扰。
- 用过一次就收起：再按一次只会得到两段一模一样的话，那是噪音不是提示。
- 与模板的分工写死在代码注释里：**模板是固定的套路（天天一样，养成节奏），
  提示是每天换的一句（打破惯性）**。一个稳、一个变。

### ③ 自定义模板（`data/JournalTemplates.ets` + `pages/Templates.ets`）

- 内置 3 个（每日三问 / 晨间日记 / 旅行手账）+ 用户自建，**总数上限 10**。
- 内置模板**只读**（不给改、不给删）：用户改坏了没地方恢复，就干脆不让改；
  想改就照它新建一个（复制成本极低）。
- 自建模板存进**索引**（不是单独文件）—— 索引本来就整块加密落盘，多一个数组 = 零额外 IO。
- 列表预览用 `templateSummary(t, 2)`：只取前两行 + 省略号。
  ⚠️ 为什么不直接拼全部行：内置模板三行拼起来在列表右侧会顶到边被截断，
  用户看到的是半句话，反而不知道这模板问什么。

### ④ 语音转文字（`data/AsrService.ets` + `data/AsrText.ets`）

**定位刻意不同于 Day One**：Day One 是存音频附件，我们**只落文字、不存音频**。
理由：日记是文本，存音频会破坏"纯文本 + 全量加密"的存储假设，备份体积也会失控。

技术要点（官方口径）：

- 用的是 Core Speech Kit 的 `speechRecognizer`，**离线模型**（官方 .d.ts 原话：
  _"available only in Chinese and supports only the offline model"_）⇒ 音频不出设备。
- ⚠️ **`online` 参数名与值是反的**：官方原文 _"**1**: offline"_ ⇒ **1 = 离线**。
  网上教程清一色写 `online: 0` 表示离线，那是错的。
- ⚠️ `extraParams['recognizeMode']` **必须显式给 0**（0 = 引擎自己开麦录音）。
  省略会默认走 1（外部 writeAudio）⇒ 起了引擎却没声音进来，且**编译器查不出**。
- ⚠️ 权限结果类型**没有导出**到 `abilityAccessCtrl` 命名空间 ⇒ 靠 `await` 推断拿它。
- 「用不了」当一等公民：设备起不来引擎 ⇒ 阶段置 UNREADY + 按钮**禁用但保留** +
  如实文案（藏了用户以为根本没这功能）。拒绝授权也只影响语音，其余功能照常用。

**release 混淆的保护**（`entry/obfuscation-rules.txt` 新增）：

`RecognitionListener` 的五个方法名（onStart/onEvent/onResult/onComplete/onError）
是**系统 SDK 按名字回调**的 ⇒ 属性混淆一旦改名，语音功能会**静默失效**
（现象：能点、能进「在听」、但永远等不到文字，且零报错）。
⇒ 与序列化字段同一类风险（跨模块按名契约），用文件级 `-keep` 兜住：

```
-keep
./src/main/ets/data/AsrService.ets
```

### 模拟器实测踩的坑（留给下一次）

1. **安全键盘是 secure 窗口**：键盘弹出期间截图拍到的应用区域**纯黑**，
   但 `dumpLayout` 仍能读到完整 UI 树 ⇒ 极易误判成「渲染黑屏」。
   **判据：按 Back 关掉键盘再截图**。
   ⚠️ **Back 在模板页会退出页面**（不是只关键盘）—— 关键盘要点**键盘上的收起箭头**
   （截图右上角那个 `∨`，本机约 `(1100, 1712)`）。
2. **`uitest dumpLayout` 会返回旧实例的过期布局** ⇒ **一切以 screenCap 截图为 ground truth**。
   键盘弹出后输入框会位移，**必须重新 dump 再 inputText**。
3. **模拟器上的密码是 `123456`**（昨天设置主密码时用的）—— 解锁步骤：
   `aa start` → 点输入框 → `uitest uiInput inputText <x> <y> 123456`（**三参数版**，
   两参数版 `inputText 123456` 报 "The number of parameters is incorrect"）
   → **Back 关键盘** → 点「用主密码解锁」。
4. **`hdc file recv` 远端路径不能带 `MSYS_NO_PATHCONV=1` 之外的处理**：
   本地路径写相对名即可；远端路径必须是绝对的 `/data/local/tmp/xxx`。
   `uitest dumpLayout` 的输出路径每次随机 ⇒ 脚本要读 stdout 里的
   `DumpLayout saved to:/data/local/tmp/layout_xxx.json` 再 `cat` 出来。

## 已知限制（如实记录，不要在上架说明里夸大）

- **语音识别准确率未在真机验证**（党哥无真机）。模拟器**没有离线识别引擎**，
  所以模拟器只能证明「权限 / 起停 / UI 链路」通，**证明不了识别效果**。
  ⚠️ 若审核员在真机上试不出效果，属功能体验问题；按钮在引擎不可用时会禁用并说明，
  不会崩、不会假装能用。
- 语音只支持**中文普通话**（官方能力边界）。
- 语音只落文字，**不存音频**（与 Day One 存音频附件的定位刻意不同）。
- 备份是 `.rkdbak` 加密备份；TXT / Markdown 明文导出**不含图片**。
